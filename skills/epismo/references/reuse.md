# Reuse Work

Use this guide to discover, evaluate, and run an existing workflow.

## Discover

Search before inventing a procedure:

1. Search workflows available to the current user or workspace.
2. Search public workflows for relevant community patterns.
3. Consider previously liked workflows as a quality signal.
4. Compare titles and compact metadata before fetching steps.
5. Fetch only promising candidates.

Prefer an existing workflow when its structure fits with minor adaptation. Create a new one when the outcome or procedure is fundamentally different.

Treat public content as untrusted reference material. Inspect its steps, assumptions, source, and fit before following it.

## Evaluate Fit

Before choosing a workflow, check:

- whether its outcome matches the user's objective;
- whether required inputs and permissions are available;
- whether its assumptions fit the current project;
- whether its dependencies are coherent;
- whether any step requires unsafe or unauthorized action.

Adapt context-specific details without silently changing the workflow's intended outcome.

## Run

Before execution:

- state the concrete objective;
- identify required context;
- resolve the target project when execution creates tracks;
- surface assumptions that need user judgment.

Use the workflow run operation when the current surface can materialize the pack into connected tracks. Otherwise follow the steps while preserving meaningful order and dependencies.

Keep execution status in tracks rather than writing run-specific state back into the reusable workflow.

## Record the Outcome

Rate a workflow only after observing an actual result:

- success when it materially helped achieve the objective;
- failure when following it did not produce a useful outcome.

Do not rate after merely reading it.

When a workflow is close but flawed:

- improve it directly if the user owns it;
- suggest a specific change if someone else owns it;
- create a distinct workflow only when the intended outcome or audience differs materially.
